# Hackathon/regtest deployment boundary

This is a single-operator regtest demo, not production custody or a production
authentication system. Preserve `.var/regtest` and the existing merchant key and
journals privately; never publish, commit or serve that directory. Backups of
node state must be private and consistent (quiesce services or use a storage
snapshot), separate from sanitized acceptance evidence.

## Supported local operator demo

Use [the runbook](final-demo-runbook.md). The production PWA build is served by
the local wallet APIs on 3030/3031, not Vite. Node APIs 3101/3102, Bitcoin RPC,
Electrs and wallet state remain on localhost/private Docker networking. The
merchant listens on 3040; the recipient service on 3050. Eclair is not involved.
The existing Docker Compose files are generated by the regtest scripts and pin
upstream images/node revisions. Preserve their volumes and configuration.

## Internet-accessible presentation

The existing ngrok HTTPS tunnel can safely target the narrow recipient service
at 3050, with request inspection disabled. Only WebFinger and account-specific
invoice acquisition are public. Public acquisition generates invoices, not spend
authority. Limit tunnel access/rate where supported; do not expose node APIs.
Use the actual assigned hostname in the service and both wallet addresses.

For a remote **human operator**, use private SSH forwarding and open the PWA on
the operator's localhost. Preserve matching local ports for Host/Origin checks:

```bash
ssh -N -L 3030:127.0.0.1:3030 -L 3031:127.0.0.1:3031 user@demo-host
```

The browser opens http://127.0.0.1:3030 and :3031 over the encrypted SSH transport.
For an audience, screen-share this UI. Do not tunnel the wallet API publicly:
the session CSRF token is not user authentication.

**Public HTTPS PWA is a deployment gap, not a supported interactive deployment.**
Static PWA assets can be hosted over HTTPS for a nonfunctional preview, but the
current integrated API intentionally rejects that public origin/host. A working
remote HTTPS PWA needs a reviewed authenticated gateway, explicit trusted-origin
support, and session/access isolation. Rewriting Origin headers or disabling the
existing checks is not a safe workaround. Those changes are outside this freeze.

**Public HTTPS merchant:** a separate ngrok tunnel may expose only port 3040
through HTTPS for inspection/compatible clients (subject to tunnel account limits).
Do not capture Authorization headers or L402 challenge bodies in tunnel logs.
Keep its node at 3102 private. However, the existing buyer accepts only explicitly
allowlisted numeric loopback HTTP origins; it cannot buy that HTTPS URL today.
The working wallet demo continues using `http://127.0.0.1:3040`, entirely on the
server. Supporting public merchant origins requires a separate security review
and transport change; do not claim public end-to-end L402 acceptance here.

Production is out of scope: authentication, multiuser isolation, rate limiting,
custody/key management, TLS origin policy, backups, chain/network migration and
operational hardening need separate work. No mainnet funds belong in this demo.
